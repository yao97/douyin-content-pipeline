# 07 · 云端归档（alist → 夸克网盘）

把本地新增的 `.m4a` + 封面增量上传到夸克网盘，为局域网设备（Mac 等）提供访问入口。

**链路**：本地文件 → 本地 alist（`:5244`）→ 夸克网盘驱动 → 夸克云。

```
D:\视频\自媒体视频库\UID..._巫师财经_发布作品\2026-05-11_巫师财经_7638279848310361009.m4a
        │
        ▼  PUT /api/fs/put   （Header: File-Path）
   alist :5244  ──[Quark driver]──►  夸克网盘 /自媒体视频库/巫师财经/2026-05-11_....m4a
```

远端布局：`/自媒体视频库/{账号昵称}/{原文件名}`（远端根可用 `--remote-root` 改）。

---

## 1. alist 认证（不靠密码）

### 1.1 结论：用**全局 API 令牌**

alist 的 `server/middlewares/auth.go` → `Auth()`：

```go
// 第一分支：直接用 Authorization 与全局设置里的 token 做常量时间比较
if subtle.ConstantTimeCompare([]byte(token), []byte(settingToken)) == 1 {
    // → 直接以 admin 身份放行，不需要密码、不需要 JWT
}
// 否则才走 JWT 分支
```

令牌即数据库 `x_setting_items(key='token')` 的值：

```sql
SELECT value FROM x_setting_items WHERE key = 'token';
```

取到后存到工作目录外的凭据文件（**不入版本库**）：

```json
// _tools/_secrets/alist.json
{ "url": "http://127.0.0.1:5244", "token": "<全局 API 令牌>" }
```

### 1.2 ⚠️ 不要试图自签 JWT

JWT 分支要求：

1. claims 里有 `Username` **和** `PwdTS`；
2. 通过 `HandleSession` 校验设备会话 —— 值是 `md5(fmt.Sprintf("%d-%s", user.ID, clientID))`，
   `clientID` 取自请求头 `Client-Id` 或查询参数 `client_id`，且必须已存在于 `x_sessions` 表。

实测所有 claim 组合一律返回 `{"code":401,"message":"token is invalidated"}`。
**不要再花时间爆破，直接走全局令牌。**

### 1.3 网络细节

- alist 是局域网服务，请求必须**绕过系统代理**：
  `urllib` 用 `build_opener(ProxyHandler({}))`，`curl` 用 `--noproxy '*'`。
  （本机有 Clash 监听 `127.0.0.1:7890`，不绕开会把 `127.0.0.1:5244` 也劫走。）

## 2. 上传协议

### 2.1 接口

```
PUT /api/fs/put
```

| Header | 说明 |
|---|---|
| `Authorization` | 全局 API 令牌 |
| `File-Path` | 远端路径，**URL 编码**（服务端会 `url.PathUnescape`） |
| `Content-Length` | 文件字节数 |
| `Overwrite` | 不等于 `"false"` 即覆盖；等于 `"false"` 且文件存在 → 403 `file exists` |
| `X-File-Md5` | **夸克侧可秒传**（本地先算好） |
| `Last-Modified` | 毫秒时间戳 → 服务端 `time.UnixMilli`，**保留原始时间** |
| `As-Task: true` | 转为后台任务（本次未使用） |

Body 是**裸文件流**（不是 multipart）。`_alist.py` 用 `http.client` 手工拼请求，1 MB 分块写。

### 2.2 ⚠️ 夸克写接口必须经 alist

直接用 Cookie 调夸克的 Web API：**读接口（`file/sort`）能通，写接口返回 HTTP 401**（需要签名）。
所以**建目录 / 上传一律走 alist 驱动**，不要绕过。

### 2.3 目录创建

`/api/fs/mkdir` 逐级幂等（`ensure_dir()` 在 `_alist.py` 里）。

## 3. ⚠️ 两个已踩的坑

### 3.1 上传后立刻回查 = 假失败

alist 的存储配置有 `cache_expiration`（曾为 30 分钟），
`/api/fs/get` 和 `/api/fs/list` 会返回**缓存中的旧目录列表** —— 刚上传的文件查不到。

**错误做法**：上传完立刻 `GET /api/fs/get` 判断成败 → 全部报「上传后回查不到远端文件」，
但实际上文件**已经上传成功**。

**正确做法**：

1. 上传后**不要**逐文件回查；
2. 改为**按目录批量强刷**比对体积：
   `list_dir(path, refresh=True)` 拉整个目录 → 与本地 size 对照；
3. 把目标存储的 `cache_expiration` 设为 `0`（本项目的 `/自媒体视频库` 存储已设为 0）。

```python
def flush_verify(al, con, dblock, queue, quiet=False):
    """按目录 list_dir(refresh=True) 批量比对 size，而不是逐文件 fs/get"""
```

校验频率：每上传 `VERIFY_EVERY`（25）个文件做一次。

### 3.2 不要与采集链并行上传

采集链会**重新下载封面**并跑 `_rename.py` **删重复文件** —— 期间文件在动。
此时并行上传会：

- 上传到半成品文件；
- 或留下「本地已删 / 云端还在」的孤儿。

**对策**：

1. 上传器内置冷却 `--min-age-min`（默认 **15** 分钟）：mtime 太新的文件本轮不传；
2. 把上传链排在采集链**结束之后**（18:00 链 ≈ 19:05 结束，上传排在 20:00）。

## 4. 本地状态库（`_upload_state.db`）

SQLite，两张表。

```sql
CREATE TABLE files (
  folder TEXT NOT NULL, account TEXT NOT NULL,
  filename TEXT NOT NULL, ext TEXT NOT NULL,
  size INTEGER NOT NULL, mtime INTEGER NOT NULL,
  md5 TEXT, remote_path TEXT, remote_size INTEGER,
  status TEXT NOT NULL,                       -- done / failed
  attempts INTEGER NOT NULL DEFAULT 0, last_error TEXT,
  first_seen TEXT NOT NULL, uploaded_at TEXT,
  PRIMARY KEY (folder, filename));

CREATE TABLE runs (                            -- 每轮运行记录
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  started_at TEXT NOT NULL, finished_at TEXT,
  duration_s REAL, scanned INTEGER, pending INTEGER,
  uploaded INTEGER, failed INTEGER, bytes INTEGER,
  jobs INTEGER, note TEXT);
```

### 4.1 增量判定

```
库里没有该文件  OR  status != 'done'  OR  size/mtime 变了   →  需要上传
```

- **重复跑幂等**，中断可续传，**不需要扫云端**。
- `--retry-failed` 把 `failed` 的也纳入本轮。
- `--stats` 只打印统计（按账号的 done/failed/体积 + 最近 5 次运行）。

### 4.2 单实例锁

`_upload_state.lock` 存 pid，配合 `OpenProcess(SYNCHRONIZE)` 判存活；
陈旧锁自动接管。防止两个上传器并发写同一个状态库。

### 4.3 磁盘余量

上传时 alist 会**先把整个文件缓存到 `D:\alist\data\temp`** 再推夸克，
所以 D: 需要留出空间：`MIN_FREE_GB = 5.0`。

## 5. CLI

```bash
python _upload_alist.py                                   # 预演：列出待传清单与体积
python _upload_alist.py --apply                           # 真实上传
python _upload_alist.py --apply --jobs 3 --max-seconds 540
python _upload_alist.py --stats                           # 只看状态库统计
python _upload_alist.py --apply --retry-failed
python _upload_alist.py --apply --folder UID..._巫师财经_发布作品
```

| 选项 | 默认 | 说明 |
|---|---|---|
| `--apply` | — | 不加则只预演 |
| `--remote-root` | `/自媒体视频库` | alist 远端根 |
| `--folder` | 全部 | 只处理指定本地目录名（可多个） |
| `--jobs` | `1` | 并发上传数 |
| `--max-files` | `0` | 本轮最多传几个（0=不限） |
| `--max-seconds` | `0` | 本轮最多跑多少秒（0=不限）**用于规避单次调用时长上限** |
| `--retry-failed` | — | 把 failed 纳入本轮 |
| `--timeout` | `3600` | 单文件上传超时秒 |
| `--min-age-min` | `15` | 冷却：mtime 太新的文件本轮不传 |
| `--no-verify` | — | 跳过目录级校验 |
| `--stats` | — | 只打印统计 |

## 6. 性能实测

| 场景 | 数值 |
|---|---|
| 小文件（封面 ~200KB） | ~2.5 s/个（瓶颈 = alist 暂存 + 夸克往返，不是带宽） |
| 大文件（m4a） | ~6.2 MB/s |
| 串行吞吐 | 19.7 文件/分 |
| `--jobs 3` 吞吐 | **67 文件/分（3.4×）**，9 分钟内 177 个文件未触发限流 |
| 全量首刷 | 2196 文件 / 8797 MB / **0 失败** |

**建议**：`--jobs 3` 是甜点；配合 `--max-seconds 540` 循环最多 6 次，
既有并发收益又不会撞上单次调用时长上限（脚本天然续传）。
