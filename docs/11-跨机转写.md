# 11 · 跨机转写（外机与生产机**不在同一网络**）

> 场景：转写是整条链最重的一环（112h 音频在本机要跑好几天，且 ASR 引擎会因 KV 溢出
> 周期性硬崩）。把**转写算力**搬到另一台带独显的 Windows 机器，产出回传，本机只做裁决与渲染。

## 1. 为什么是「只交 raw」，不是「交 md」

`_asr_registry.json` 是增量重跑的**唯一真相**，而它的写法是「整表回写」——
两台机器同时写会**静默抹掉对方的改动**（详见 `docs/09-踩坑与排障.md`）。
所以：

| 角色 | 写什么 | 不写什么 |
|---|---|---|
| 外机 | `_asr_raw/<vid>.json`（转写原文） | ❌ 不写 `_asr_registry.json`、❌ 不出 md |
| 本机 | 注册表（`registry`）+ md（`stage2`） | — |

好处：① 天然无并发冲突 ② 关键词 / LLM 摘要 / 封面 / 命名规范 100% 与本机一致
③ raw 极小（平均 **34 KB/条**），回传成本可忽略。

### 体积账（真实口径）

| 走法 | 单向流量 |
|---|---|
| 外机整链跑、只回 raw | 源 **3.68 GB 已在夸克**（本机零上传）＋ 回传 raw **~11 MB**/327 条 |
| 改「把音频推给远端 8766 算」 | **12.03 GB**（112.1h ÷ 879s ≈ 459 段 × ~27MB） |

→ 差 **400 倍**。**不同网络下只有前者成立**（后者还需把 8766 暴露到公网，
而 8766 的 `/api/*` 零鉴权 —— 绝对不要）。

## 2. 外机部署清单

### 2.1 引擎（`video-analyzer` 工程，可独立于本机）

```bash
git clone https://github.com/yao97/video-analyzer.git
cd video-analyzer/backend
git clone https://github.com/HaujetZhao/Qwen3-ASR-GGUF.git qwen3_asr_gguf_src
pip install onnxruntime-directml pydub scipy gguf srt requests flask
```

模型（解压到 `backend/qwen3_asr_models/`）：

- `Qwen3-ASR-1.7B-gguf.zip`（1.3GB）
- `Qwen3-ForceAligner-0.6B-gguf.zip`（481MB，时间戳必需）

llama.cpp 二进制：**Windows Vulkan 版、必须 b8996**，DLL 放到
`qwen3_asr_gguf_src/qwen_asr_gguf/inference/bin/`。

> ⚠️ **b10229+ 与引擎不兼容，会 access violation** —— 这是硬坑，别用最新版。

自检：`python transcribe_server.py --host 0.0.0.0 --port 8766` 起得来、页面能开即可。

### 2.2 流水线代码

```bash
git clone https://github.com/yao97/douyin-content-pipeline.git
# 代码在 core/03-asr/：把 asr_batch.py / lib_source.py / _stage2_daemon.py /
#                     checkpoint.py / progress.py / webui.py / remote_handoff.py
#                     拷到外机的「知识库目录」（= 下面的 WB_OUT_ROOT）
```

> 外机只跑 `asr_batch.py stage1`，其实只需要 `asr_batch.py` + `lib_source.py` 两个文件。

### 2.3 环境变量（**代码零改动**，全部路径靠环境变量指过去）

| 变量 | 说明 |
|---|---|
| `WB_SOURCE=lib` | 必设，否则退回旧源「关注」 |
| `WB_OUT_ROOT` | 外机的知识库目录（`_asr_raw/` 会建在这里） |
| `WB_LIB_ROOT` | 外机的视频库目录（放从夸克拉的 m4a + 封面） |
| `WB_FFMPEG` | 外机 ffmpeg.exe 的绝对路径（推荐 `imageio-ffmpeg` 的静态二进制） |
| `WB_ASR_API` | 默认 `http://127.0.0.1:8766`，外机跑本地引擎就不用改 |
| `WB_FACTS` | 可选。抖音号映射；**不设也行**（本机 `syncmeta` 事后补） |

LLM 密钥（`_llm_config.sh`）外机**不需要** —— 摘要由本机渲染时生成。

## 3. 三步流程

### ① 本机导出清单

```bash
cd <本机知识库目录>
python remote_handoff.py export --out _handoff/to_remote
# 想分批：--author 魏远麟  /  --limit 50
```

产出 `to_remote.json`（机器可读）+ `外机待转写清单.md`（人读，含分作者统计与明细表）。
清单里每条给出 `src_rel` / `cover_rel`（**相对库根**），外机据此从夸克挑文件。

### ② 外机拉源 + 转写

```bash
set WB_SOURCE=lib & set WB_OUT_ROOT=D:\kb & set WB_LIB_ROOT=D:\lib & set WB_FFMPEG=D:\ffmpeg.exe
python asr_batch.py stage1
```

只产 `_asr_raw/<vid>.json`。长视频（≥20 分钟）会**自动切片**并合并成一条，
每段结果独立落盘可断点续跑；引擎崩了客户端会自愈重提。

把 `_asr_raw/` 里新增的 json 打包回传夸克即可（**别传 wav / `_slice_tmp/`**）。

### ③ 本机合入 + 渲染

```bash
python remote_handoff.py import <解压目录>            # 先 dry-run 看报告
python remote_handoff.py import <解压目录> --apply     # 合入 + 重建注册表
python _stage2_daemon.py                              # 渲染 raw → md（若已在跑会自动捡到）
```

`import` 会做四件事：**① 校验**（空 text / duration 无效 / 字数过短一律拒收）
**② 去重**（本机已转写的跳过）**③ 用本机源元数据补全**标题/作者/抖音号/**封面路径**
**④ 原子落盘**（`.part` → `os.replace`，stage2 轮询不会读到半截文件）。
最后 `build_registry()` 重建注册表。

> 为什么非要 ③：raw 里的 `cover` 是**外机的绝对路径**，本机不存在 → stage2 会
> 「md 生成了但没有同名封面」。import 时按 vid 从本机库里重新解析出封面路径。

## 4. 分工与避坑

- **别两台同时转同一条**。要么按作者/`--limit` 切分，要么本机先停 `stage1`
  （`_stage1.lock` 的 pid 存活判定会让第二个实例自己退出，但**重复转写**是白烧时间）。
- 外机转完的条目，本机 `_todo()` 自然不再列出（注册表已 ok）→ 不会重复派发。
- 源文件拉取：夸克 `/自媒体视频库/<账号目录>/`，**保持同目录结构**（`lib_source.py`
  靠目录名解析作者、靠 CSV / 文件名解析作品ID）。
- 外机不需要 `Data/UID*.csv`；文件名里已带作品ID与日期，作者取自目录名。
- 若某条在外机反复失败：先按 `docs/09-踩坑与排障.md` 的「失败归因三步法」判，
  AAC 码流损坏类**只能重新下载**，换机器也没用。
