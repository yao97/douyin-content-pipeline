# 11 · 跨机转写（外机与生产机**不在同一网络**）

> 场景：转写是整条链最重的一环（112h 音频在本机要跑好几天，且 ASR 引擎会因 KV 溢出
> 周期性硬崩）。把**转写算力**搬到另一台带独显的 Windows 机器，产出回传，本机只做裁决与渲染。

## 1. 为什么是「只交 raw」，不是「交 md」

`_asr_registry.json` 是增量重跑的**唯一真相**，而它的写法是「整表回写」——
两台机器同时写会**静默抹掉对方的改动**（详见 `docs/09-踩坑与排障.md`）。
所以：

| 角色 | 写什么 | 不写什么 |
|---|---|---|
| 外机 | `_asr_raw/<vid>.json`（转写原文） | ❌ 不写 `_asr_registry.json`、❌ 不出 md |
| 本机 | 注册表（`registry`）+ md（`stage2`） | — |

好处：① 天然无并发冲突 ② 关键词 / LLM 摘要 / 封面 / 命名规范 100% 与本机一致
③ raw 极小（平均 **34 KB/条**），回传成本可忽略。

### 体积账（真实口径）

| 走法 | 单向流量 |
|---|---|
| 外机整链跑、只回 raw | 源 **3.68 GB 已在夸克**（本机零上传）＋ 回传 raw **~11 MB**/327 条 |
| 改「把音频推给远端 8766 算」 | **12.03 GB**（112.1h ÷ 879s ≈ 459 段 × ~27MB） |

→ 差 **400 倍**。**不同网络下只有前者成立**（后者还需把 8766 暴露到公网，
而 8766 的 `/api/*` 零鉴权 —— 绝对不要）。

## 2. 外机部署清单

### 2.2 流水线代码

git clone https://github.com/yao97/douyin-content-pipeline.git
# 代码在 core/03-asr/：把 asr_batch.py / lib_source.py / _stage2_daemon.py /
#                     checkpoint.py / progress.py / webui.py / remote_handoff.py

### 2.3 环境变量（**代码零改动**，全部路径靠环境变量指过去）

| 变量 | 说明 |
|---|---|
| `WB_SOURCE=lib` | 必设，否则退回旧源「关注」 |
| `WB_OUT_ROOT` | 外机的知识库目录（`_asr_raw/` 会建在这里） |
| `WB_LIB_ROOT` | 外机的视频库目录（放从夸克拉的 m4a + 封面） |
| `WB_FFMPEG` | 外机 ffmpeg.exe 的绝对路径（推荐 `imageio-ffmpeg` 的静态二进制） |
| `WB_ASR_API` | 默认 `http://127.0.0.1:8766`，外机跑本地引擎就不用改 |
| `WB_FACTS` | 可选。抖音号映射；**不设也行**（本机 `syncmeta` 事后补） |

LLM 密钥（`_llm_config.sh`）外机**不需要** —— 摘要由本机渲染时生成。

## 3. 搬运通道（夸克网盘）

两端约定一个固定的**交接目录**，都在夸克里：

```
自媒体视频库/_跨机交接/
├── to_remote/     ← 本机放清单（3 个文件，~330 KB）
└── from_remote/   ← 外机放回传包（1 个 zip，~11 MB）
```

### 3.1 通道选择（**踩过的坑，别走错**）

| 通道 | 列目录 | 上传 | 下载 |
|---|---|---|---|
| **alist**（Quark 驱动） | ✅ | ✅（采集流水线每天在用） | ❌ **直链被夸克 CDN 拒**：`RequestDeniedByCallback` / `require login` |
| **夸克官方 CLI**（开放平台令牌） | ⚠️ **受限视图** | ✅ 但只在它自己的沙箱根下 | ✅ 但够不到 `自媒体视频库` |
| **夸克 web API + 会话 cookie** | ✅ | 需签名，不做 | ✅ **可用**（本工具走这条） |

结论：**列目录/上传走 alist，下载走夸克 web API**。

- 夸克官方 CLI 的令牌是**受限视图**（`browse --parent-fid 0` 只看到 2 个目录；
  直接按源库 fid 取会返回 `12005 文件无权限`），所以它做不了这条链的搬运。
- alist 的下载直链指向 `dl-pc-zb.pds.quark.cn`，实测 403 ——
  这是 **alist 侧的既有问题**（不影响它的上传与列目录）。
- 夸克 web 通道的 cookie 直接复用 alist 存储配置里的那份
  （`/api/admin/storage/list` → `addition.cookie`），不需要额外登录；
  `fs/get` 返回的 `id` 就是夸克的文件 FID，拿它调 `file/download` 换一次性直链。

### 3.2 ⚠️ 目录名对不上（最容易踩）

| | 目录名 |
|---|---|
| 夸克网盘（`自媒体视频库/` 下） | `魏远麟律师 广州` |
| 本机库（= 清单 `src_rel` 的第一段） | `UID3303366684053592_魏远麟律师 广州_发布作品` |

映射规则以采集侧上传器 `_upload_alist.account_of()` 为**权威**（`remote_handoff` 直接调它，
避免两处规则漂移）。所以清单里给**两套路径**：

- `src_quark` —— **从哪取**（夸克上相对 `自媒体视频库/` 的位置）
- `src_rel` —— **放到哪**（外机本地相对 `WB_LIB_ROOT` 的位置）

## 4. 三步流程

### ① 本机导出 + 发布清单

```bash
cd <本机知识库目录>
python remote_handoff.py export          # 出清单（to_remote.json + 两份 md）
python remote_handoff.py publish         # 推到夸克 自媒体视频库/_跨机交接/to_remote/
python remote_handoff.py publish --check # 只比对远端现状，不上传
```

`export` 支持 `--author 魏远麟` / `--limit 50` 分批。清单里每条给出
`src_rel` / `src_quark` / `cover_rel` / `cover_quark` 与 `size` / `dur_sec`。
`外机操作说明.md` 是**给外机看的完整操作手册**（含目录改名脚本）。

### ② 外机拉源 + 转写

外机只需下 4 个夸克目录（约 6 GB），改名成 `src_rel` 的目录名，设好环境变量后：

```bash
python asr_batch.py stage1
```

只产 `_asr_raw/<vid>.json`。长视频（≥20 分钟）**自动切片**并合并成一条，
每段独立落盘可断点续跑；引擎崩了客户端会自愈重提。

回传：把清单里那些 vid 的 json 打成一个 zip，传到
夸克 `自媒体视频库/_跨机交接/from_remote/`。（`外机操作说明.md` 里有现成的 PowerShell 片段。）

### ③ 本机一键收包 + 渲染

```bash
python remote_handoff.py fetch            # 先 dry-run：拉最新 zip + 预演
python remote_handoff.py fetch --apply    # 合入 + 重建注册表
python _stage2_daemon.py                  # 渲染 raw → md（若已在跑会自动捡到）
```

`fetch` = **经 alist 列目录挑最新 zip → 走夸克 web 通道下载 → 自动解压 → 导入**。
也可以手动下载后 `python remote_handoff.py import <目录|zip> --apply`。

`import` 做四件事：**① 校验**（空 text / duration 无效 / 字数过短一律拒收）
**② 去重**（本机已转写的跳过）**③ 用本机源元数据覆盖** `author/pub/title/account/kind/aid/video/cover`
**④ 原子落盘**（`.part` → `os.replace`，stage2 轮询不会读到半截文件），最后 `build_registry()` 重建注册表。

> 为什么非要 ③：raw 里的 `video` / `cover` 是**外机的绝对路径**，本机不存在 ——
> `cover` 不存在会让 md「生成了但没有同名封面」，`video` 不换则 raw 溯源失真。
> import 时按 vid 从本机库里重新解析出真实路径，顺带把外机可能填错的元数据一并纠正。
> 若本机确实找不到封面，会明确告警列出 vid（而不是静默出无封面 md）。

## 5. 分工与避坑

- **别两台同时转同一条**。要么按作者/`--limit` 切分，要么本机先停 `stage1`
  （`_stage1.lock` 的 pid 存活判定会让第二个实例自己退出，但**重复转写**是白烧时间）。
- 外机转完的条目，本机 `_todo()` 自然不再列出（注册表已 ok）→ 不会重复派发。
- **外机不写注册表、不出 md、不碰 `_slice_tmp` 回传**。
- 外机不需要 `Data/UID*.csv` / `facts.json`；文件名里已带作品ID与日期，
  作者取自目录名（改名后 `UID…_作者_发布作品` 就自洽了）。
- 外机下的目录里同名 `.webp` 封面是历史遗留，`.jpeg` 优先，两个都在也无妨。
- 若某条在外机反复失败：先按 `docs/09-踩坑与排障.md` 的「失败归因三步法」判，
  AAC 码流损坏类**只能重新下载**，换机器也没用。
- 回传包里塞了非 json / 非法路径的 zip 会被**拒绝解压**（防目录穿越），
  不合格条目逐条列出原因，不会污染本机 raw。
