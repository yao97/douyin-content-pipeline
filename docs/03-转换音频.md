# 03 · 转换音频

转写只需要声音。本环节把「视频」变成「音轨」，有两条路：**抽流**（本地转）和**音频直下**（根本不视频）。

---

## 1. 抽流：mp4 → m4a（`_to_audio.py`）

```bash
python _to_audio.py            # 只转换，保留 mp4
python _to_audio.py --delete   # 转换成功后删除 mp4（每日链路用这个）
```

### 1.1 两级策略

```python
# 1) 无损抽流（秒级完成，不重编码）
ffmpeg -y -i in.mp4 -vn -acodec copy out.__tmp.m4a
# 2) 兜底：重编码 64k 单声道（ASR 足够）
ffmpeg -y -i in.mp4 -vn -acodec aac -b:a 64k -ac 1 out.__tmp.m4a
```

先写临时文件 `*. __tmp.m4a`，校验体积 > 1KB 后再 `replace()` 成正式名 ——
保证**不会留下半成品 m4a**（下游按「m4a 存在即已转换」判断，半成品会被误当成品）。

### 1.2 已转换判断

```python
if m4a.exists() and m4a.stat().st_size > 1024:
    return True   # 幂等：重复运行安全
```

### 1.3 扫描范围（易踩坑）

```python
for folder in sorted(set(ROOT.glob("UID*_发布作品")) | set(ROOT.glob("MID*"))):
```

> ⚠️ **必须同时含 `MID*`**。合集目录曾经被漏掉，导致 37 个作品的 mp4 一直不转、白占约 22 GB 磁盘。

### 1.4 收益实测

| 项 | 数值 |
|---|---|
| 4 小时播客：视频 → 音频 | 668 MB → 81.8 MB（**省 88%**） |
| 时长一致性 | 与视频完全一致 |
| 失败率 | 0（无损抽流几乎不会失败） |

## 2. 音频直下（`_audio_direct.py`）

正常流程「下视频 → 抽音轨 → 删视频」白下了 8 倍的画面数据。
抖音的 Detail 接口其实**直接提供纯音频档**，拉它就能完全跳过视频。

### 2.1 音频档结构

```
video.bit_rate_audio = [ { audio_extra, audio_meta, audio_quality } ]   # 通常只有 1 档
  audio_meta = {
      bitrate: ~193000,
      size: <bytes>,
      media_type: "audio",
      format: "dash",
      url_list: { main_url, backup_url }
  }
```

> ⚠️ `gear_name` / `bit_rate` 在 **`audio_meta` 内部**，不在元素顶层。路径含 `media-audio-und-mp4a`。

### 2.2 音质档

```python
def pick_stream(bras, quality):      # quality: small | mid | best（默认 small）
    items = audio_gears(bras)        # 按码率升序
    return items[0] if quality == "small" else items[-1] if quality == "best" \
           else items[len(items) // 2]
```

### 2.3 ⚠️ 限流陷阱（最关键的一条）

抖音在限流时会返回**降级响应**（`content-length` 约 60 KB，正常 125 KB+），
其中的 `bit_rate` / `bit_rate_audio` **被整段裁掉** —— 表现出来就像「这个作品没有音频档」。
而且**越早的作品越容易被裁**。

因此：

- **绝不能用并发探测得出的「无音频档」结论**（并发更容易触发限流）。
- 真「无音频档」的判定标准：**退避重试后 `bit_rate` 条数仍非 0，且确实没有 audio 档**。
- 脚本已内置：`picked` 为空时 `await asyncio.sleep(2.5)` 后重取一次详情再判定。

### 2.5 CLI

```bash
python _audio_direct.py                                    # dry-run：统计可省多少 + 覆盖率
python _audio_direct.py --apply                            # 只补缺失的 m4a
python _audio_direct.py --apply --folder MID..._合集作品     # 限定目录
python _audio_direct.py --apply --fallback-video           # 无音频档 → 最小 mp4 抽音轨
python _audio_direct.py --apply --delete-mp4               # 音频就绪后删同作品 mp4
```

| 选项 | 默认 | 说明 |
|---|---|---|
| `--quality` | `small` | 音质档 |
| `--jobs` | `2` | 并发数（对接口友好） |
| `--sample` | `8` | dry-run 抽样个数 |

**返回状态码**：`ok` / `fallback` / `skip` / `no-audio` / `fail` / `invalid`。
`ok` + `fallback` 都算成功；`no-audio` 是「真的没有音频档」；`invalid` 是「下到了但格式校验不过」。

### 2.6 收益实测

| 场景 | 视频 | 音频直下 | 节省 |
|---|---|---|---|
| 4 小时播客 | 668 MB | 81.8 MB | 88% |
| 短作品（平均） | ~55 MB | ~6.8 MB | ~88% |

音频档真实覆盖率约 **85%~95%**（越老的作越容易缺失）。

### 3.1 其它注意

- 容器的 m4a 输出可能因为源流容器不受支持而失败 → 走 64k/128k 重编码兜底。
- 只有 `.mp4` 存在、`.m4a` 尚未生成的作品，在转写侧会被当作「还没稳定」，
  需等 mtime 超过 `WB_LIB_FRESH_SEC`（默认 120s）才会被排进转写任务 —— 防止转写半个文件。
- 音频文件时间戳 `{时间戳}-视频-...` 前缀与标准名 `{日期}_{昵称}_{ID}.m4a` 会被**同时**识别为「已存在」，
  判断存在性时必须两种前缀都接受（见 [05-命名与封面](05-命名与封面.md)）。
