# 05 · 命名与封面

---

## 1. 文件命名规范

```
账号作品： {发布日期}_{账号昵称}_{作品ID}.{ext}
          2026-05-11_AAA麟西_7638279848310361009.m4a
图集多图： {发布日期}_{账号昵称}_{作品ID}_{n}.jpeg      # 保留 _N 序号
合集作品： {YYYY-MM-DD HH.MM.SS}-视频-{合集名}-{标题}.m4a
```

### 1.1 为什么需要改名

工具原始命名形如：

```
2026-09-07 11.42.24-视频-这很容易-抄底拼多多，A轮入宁德... #投资.m4a
```

问题：以「发布时间 + 描述」为键，描述可截断、可重复、含特殊字符，
且**下载器重下时按旧名查不到会重下一次**。

改成 `{日期}_{昵称}_{作品ID}` 后，键唯一且稳定。

### 1.2 改名依据（`_rename.py`）

映射来自 `Data/*.csv`：`(账号昵称, 发布时间) → 作品ID`。

```python
key = (nick, ts.replace(":", "."))          # 发布时间冒号换点
ids = sorted(set(mapping.get(key, [])))     # CSV 多次采集会重复追加同一 ID，先去重
```

- **`set` 去重是必须的**：同一账号多次采集会让同一个作品在 CSV 里出现多行。
- 多 ID 歧义 / 无映射 → 跳过并打印（不猜）。
- 目标名已存在 → 判为「重复下载」，**删旧命名副本**（走 Win32 `DeleteFileW`，绕 safe-delete shim）。

```bash
python _rename.py           # 只预览（dry-run）
python _rename.py --apply   # 真正改名
```

## 2. ⚠️ 命名一致性陷阱（踩过两次，代价很大）

**合集目录 `MID_*` 不参与 `_rename.py`**，文件保持工具原始命名
（`{时间戳}-视频-{合集名}-{标题}.m4a`，**文件名里没有作品ID**）。

因此：**凡按「新命名前缀」判断存在性的脚本，都必须同时接受「原始命名前缀」**，
否则会把整个合集目录误判为「缺失」。

| 脚本 | 只认新名的后果 |
|---|---|
| `_repair.py` | **会删掉 DB 记录 → 下次重下几十 GB**（最严重） |
| `_cover_audit_fix.py` | 每轮误报缺封面，并重复下载封面 |

正确写法：

```python
pat_new = folder / f"{ts[:10]}_{nick}_{wid}"        # 标准名
pat_old = folder / f"{ts.replace(':', '.')}-"        # 工具原始名
if files_exist(pat_new, exts) or files_exist(pat_old, exts):
    ...  # 视为已落盘
```

新增校验脚本请复用 `_mix_verify.py` 的「CSV 发布时间 → 文件名前缀」口径：

```python
def prefix(ts: str) -> str:
    """'2025-10-17 12:08:27' -> '2025-10-17 12.08.27'"""
    d, _, t = ts.partition(" ")
    return f"{d} {t.replace(':', '.')}"
```

## 3. 封面

### 3.1 命名与形态

- 标准名封面：`{发布日期}_{昵称}_{作品ID}.{jpeg|jpg|webp|png}`
- 图集多图：`{发布日期}_{昵称}_{作品ID}_{n}.{ext}`
- 格式由抖音接口决定（可能是 `.jpeg` 也可能是 `.webp`），不要写死扩展名。
- 工具开关：`static_cover: true` 才会把静态封面存成 `.jpeg`；
  `dynamic_cover` 是动图 `.webp`。

### 3.2 ⚠️ 图集/实况也必须有「标准名」封面

否则严格匹配的工具会判「缺封面」，每轮重复下载。

**补齐方式**：只有 `_N` 序号图时，**用首图复制一份**成标准名。

```python
suffixed = sorted(p for p in imgs if p.stem.startswith(stem + "_"))
if suffixed and not (folder / (stem + suffixed[0].suffix)).exists():
    shutil.copy2(suffixed[0], folder / (stem + suffixed[0].suffix))
```

### 3.3 封面审计与补齐（`_cover_audit_fix.py`）

```bash
python _cover_audit_fix.py           # 审计 + 补齐
python _cover_audit_fix.py --check   # 只报告不下载
```

**命中条件（任一即视为已有封面）**：

1. 已改名封面 `{date}_{nick}_{id}[_N].*`
2. 工具原始命名封面 `{发布时间冒号换点}-...`
   （合集 `MID_` 目录不走改名，必须算命中，否则每轮误报）

**三级兜底下载链**：

```
① CSV「静态封面」URL
② CSV「动态封面」URL
③ Detail 接口 images[]（图集，多图时命名 {stem}_{n}.jpeg）
④ Detail 接口 video.cover / video.origin_cover
```

> ⚠️ 调 Detail 接口时**必须挂 `_tk_auth.inject(p)`**，否则 tester 缺 uifid/msToken 会被风控，
> 拿不到 images/cover。

> ⚠️ 下载成功判据是 `size > 3000` 字节，否则删掉重试（避免存下 404 页面）。

### 3.4 命名同步到知识侧

md 与封面**同名不同扩展名**，随源文件走。
不允许裸 `作品ID.jpg`（后续按作品ID反查会乱）。
