# 02 · 下载视频

## 1. 三种采集方式

| 方式 | 脚本 | 取什么 | 适用 |
|---|---|---|---|
| 账号批量 | `_pipeline.py`（驱动 TikTokDownloader） | 视频/图集/实况 + 封面 + 30 列 CSV | 日常主力 |
| 合集批量 | `_dl_mix.py`（同上，切 `run_command`） | 指定 collection 的全部作品 | 长播客合集 |
| 只看清单 | `_acct_fetch.py` | 仅元数据 CSV + 封面（**不下视频**） | 新账号快速入库 |

---

## 2. 账号批量采集

### 2.1 入口与执行流

`_pipeline.py` 是编排层，做四件事：

1. **配置对齐**：把 `URLS` 写进 `Volume/settings.json` 的 `accounts_urls`
   （`earliest` 首次全量必须留空，否则工具会提前终止）；
   同时把 `run_command` **强制拉回** `"5 1 1 Q"`（防止上一次合集模式残留导致误跑）。
2. **磁盘预检** `ensure_space()`：低于 `MIN_FREE_GB`（默认 20）时先回收残留 mp4，仍不足则
   `exit=2` 并跳过本轮（**exit=2 不要重试**）。
3. **两阶段下载**：phase1 只跑第 1 个账号试水，成功再 phase2 全量。
4. **收尾**：调用 `_rename.py --apply` 统一命名。

### 2.2 工具命令编码

`run_command` 是空格分隔的菜单路径（**1-based**）：

```
"5 1 1 Q"   终端交互模式 → 批量下载账号作品(抖音) → 使用 accounts_urls → 退出
"5 5 1 Q"   终端交互模式 → 批量下载合集作品(抖音) → 使用 mix_urls   → 退出
```

> ⚠️ **索引 6 = 后台监听模式（剪贴板监听），会永久卡死**。官方文档里的示例已过时。

### 2.3 增量机制

工具的 `is_skip()` = `is_downloaded(id) OR is_exists(目标路径)`：

- `is_downloaded(id)`：查 `Volume/DouK-Downloader.db` 的 `download_data(ID)` 表。
- `is_exists(path)`：查工具自己命名的目标文件是否已存在。

**任一命中即跳过**。所以增量是天然的，不需要额外维护状态。

## 3. 合集采集

`_dl_mix.py` 一键完成：

1. 临时改写 `settings.json`：写入 `mix_urls` + `run_command = "5 5 1 Q"`；
2. 跑 `main.py`（超时 4 小时）；
3. `finally` 恢复原 `run_command`（`mix_urls` 保留，便于下次增量）。

产物落到 `MID{合集ID}_{标题}_合集作品/`，CSV 前缀 `MID_`。

配置位置在脚本顶部：

```python
MIX_URL = "https://www.douyin.com/collection/<合集ID>/1"
```

> ⚠️ **耗时量级差异**：长播客合集单文件可达 1GB+，实测 37 个作品约 25 分钟，
> 远慢于账号增量（增量通常只有零星几条）。跑批脚本的调用超时要相应放大。

## 4. 新账号入库（`_acct_fetch.py`）

只拉元数据清单，**不下载视频**。存在的意义：`_audio_direct.py` 是按 `Data/*.csv` 驱动工作的，
先有清单才能「只下音频」。

```bash
python _acct_fetch.py <sec_uid|主页URL>              # dry-run：只报数量
python _acct_fetch.py <sec_uid|主页URL> --apply      # 写 CSV + 建目录
python _acct_fetch.py <sec_uid|主页URL> --apply --covers
```

产出：

1. `Data/UID{uid}_{昵称}_发布作品.csv`（与工具原生格式**完全一致的 30 列**）
2. `<同名目录>/`
3. `--covers` 时下载静态封面 `{发布日期}_{昵称}_{作品ID}.{jpeg|webp|png}`

CSV 已存在时按 `作品ID` 去重追加，可反复安全执行。

### 4.1 sec_uid 解析

```python
SEC_RE = re.compile(r"(MS4wLjAB[A-Za-z0-9_\-]+)")
```

从分享链接 / 主页 URL 里正则抠出 `MS4wLjAB...`。

> ⚠️ **纯数字的「抖音号」（如 `75824640534`）无法低成本自动解析成 sec_uid**。
> 已验证走不通的路径：SSR 页面 -404、`iesdouyin` 接口「参数不合法」、
> 搜索页验证码、页面 fetch 缺签名。
> **正确做法：让用户提供主页分享链接**（App → 分享 → 复制链接）。
> 短链 `v.douyin.com/xxx` 可跟随 302 跳转到 `iesdouyin.com/share/user/MS4wLjAB…` 拿到 sec_uid。

## 5. 分页风控：只抓到第一页（重要）

### 5.1 症状

- 第 1 页正常返回 18 条；第 2 页起响应头出现
  `whale-decision-custom: black_no_login`，body 仅 17 字节 `{"status_code":0}`。
- 工具日志报「配置文件 cookie 参数未登录，数据获取已提前结束」。

### 5.2 根因

`src/testers/Params`（工具内部用于独立调接口的测试器）：

1. 读的是 `Volume/test_cookie.ini`，**与 `settings.json` 里的正式 Cookie 不是同一份**，
   前者常常已经过期；
2. **从不注入 `uifid` 和 `msToken`**。缺这两个值时抖音只放第一页。

### 5.3 修法（`_tk_auth.py`）

与工具自身的 `Parameter.update_params_offline` / `set_uif_id` 保持一致：

1. 用 `Volume/settings.json` 的正式 Cookie 覆盖 `header` 与 `cookie_str`；
2. `uifid` 从 Cookie 的 `UIFID` 键取值，写进 `API.params` 和请求头；
3. `msToken` 在线调 `MsToken.get_real_ms_token()` 获取；失败则退化为随机值（可能仍被风控）。

```python
import _tk_auth
async with Params() as p:
    await _tk_auth.inject(p)          # ← 必须挂上，否则只拿第一页
    ...
```

**自己写脚本读 tester 时必须挂上**。`_acct_fetch.py` / `_audio_direct.py` / `_cover_audit_fix.py`
都已内置。

### 5.4 其它必查项

- `Params.max_pages` 默认只有 **2** —— 全量拉取必须设成 `99999`。
- 默认 HTTP 客户端超时只有 5 秒，全分页容易超时 → 重建 `create_client(timeout=30)`。

## 6. 磁盘闸门

```python
def ensure_space():
    f = free_gb()
    if f >= MIN_FREE_GB:
        return True
    run_helper("_to_audio.py", "--delete")   # 先回收残留 mp4
    if free_gb() < MIN_FREE_GB:
        return False                          # 仍不足 → 放弃本轮
    return True
```

落地原因：曾因 D: 写满触发 `OSError(28) 'No space left on device'`，
整批下载中断且 DB/落盘状态不一致（部分记录已写但文件只写了一半）。

约定：返回 False 时写日志「已跳过（磁盘不足）」并 `exit=2`；
**自动化里看到 exit=2 不要重试**，那是设计内的保护动作。

## 7. 已知的「假成功」

接口被间歇性拦截时，工具会「0 下载但报成功」。因此**跑完必须校验**：
用 `_repair.py` 的缺失计数核对，缺了就重跑。
