# 08 · 每日自动化

两条独立的定时链路，各自负责「采集」和「归档」。跑完都做自检，并要求**双 0**。

| 时间 | 名称 | 链路 |
|---|---|---|
| **18:00** | 采集链 | 磁盘预检 → 修数据 → 账号增量 → 合集增量 → 转音频 → 回填 DB → 补封面 → 双 0 终检 |
| **20:00** | 归档链 | 增量上传夸克网盘 |

> 两条链路的时间差（2 小时）是**刻意留的安全间隔**：
> 上传器有 15 分钟冷却，且不能与采集链并行（见 [07-云端归档](07-云端归档.md#32-不要与采集链并行上传)）。

## 1. 18:00 采集链

### 1.1 步骤

```bash
cd D:\视频\自媒体视频库

# ① 磁盘预检（写入闸门；不足时先回收残留 mp4）
#    由 _pipeline.py 内部 ensure_space() 执行，MIN_FREE_GB 默认 20

# ② 修数据：把「库有记录但文件缺失」的作品放行重下，清孤儿缓存
python _tools/TikTokDownloader/_repair.py --apply

# ③ 账号增量采集（N 个账号；含 phase1 试水 + 磁盘闸门 + 自动改名）
python _tools/TikTokDownloader/_pipeline.py
#    ← exit=2 表示「磁盘不足已跳过」，不要重试

# ④ 合集增量采集
python _dl_mix.py

# ⑤ mp4 → m4a 并删除源视频回收磁盘
python _to_audio.py --delete

# ⑥ 已落盘作品回填下载 DB（防次日重复下载视频）
python _seed_done.py --apply

# ⑦ 封面审计 + 三级兜底补齐
python _cover_audit_fix.py

# ⑧ 双 0 终检
python _tools/TikTokDownloader/_repair.py        # 缺失计数须为 0
python _seed_done.py                             # 待回填计数须为 0
```

### 1.2 结束时间

整链约 **19:05** 结束（视新增量与合集长度浮动；长播客合集单个文件可达 1GB+，
实测 37 个作品约 25 分钟）。

### 1.3 失败处置

| 现象 | 处置 |
|---|---|
| `_pipeline.py` `exit=2` | **磁盘不足已跳过，不要重试**；先清理磁盘或调低 `MIN_FREE_GB` |
| 某账号 0 下载但报成功 | 接口被间歇拦截的**假成功**；用 `_repair.py` 缺失计数确认后重跑该账号 |
| 终检缺失计数 ≠ 0 | 说明有作品没下到 → 重跑 `_pipeline.py` |
| 终检待回填 ≠ 0 | 跑 `_seed_done.py --apply` |
| 磁盘 `OSError(28)` | 说明闸门被绕过或阈值过低；检查 `MIN_FREE_GB` |

## 2. 20:00 归档链

```bash
cd D:\视频\自媒体视频库
python _upload_alist.py --apply --jobs 3 --max-seconds 540
```

自动化里通常写成「**循环最多 6 次**」的形式，规避单次调用的时长上限；
脚本本身天然续传（SQLite 状态库记录已传文件），中断后再跑即可继续。

### 2.1 参数理由

| 参数 | 值 | 理由 |
|---|---|---|
| `--jobs` | `3` | 实测 3.4× 吞吐（67 文件/分），9 分钟 177 文件无触发限流 |
| `--max-seconds` | `540` | 单次调用不超过 9 分钟 |
| `--min-age-min` | `15`（默认） | 冷却，避免传到「正在被改名/删除」的文件 |

### 2.2 先看统计再决定

```bash
python _upload_alist.py --stats
```

输出按账号的 `done / failed / 体积` 与最近 5 次运行记录。
`failed > 0` 时用 `--apply --retry-failed` 补传。

## 3. 前置依赖检查（每次跑前应确认）

| 依赖 | 检查方式 | 不满足时 |
|---|---|---|
| alist 在线 | `curl --noproxy '*' http://127.0.0.1:5244/api/fs/list` | 启动 `D:\alist\start.bat` |
| 采集侧 Cookie 有效 | `_cookie_health.py` | 重新注入 Cookie |
| 磁盘余量 | `_pipeline.py` 自带闸门 | 自动回收 / 跳过 |
| 转写服务（若要跑转写） | `curl --noproxy '*' http://127.0.0.1:8766/` | 由 nssm 服务自动重启，**不要手工 Popen** |

## 4. 常驻服务速查

| 服务 | 端口 | 守护方式 | 重启方式 |
|---|---|---|---|
| ASR 转写 | `127.0.0.1:8766` | Windows 服务 `VideoAnalyzer-Transcribe`（nssm，Auto） | `Restart-Service VideoAnalyzer-Transcribe` |
| 转写看板 | `127.0.0.1:8770` | 单实例锁 `_webui.lock` | `POST /api/quit` 后重新拉起（**不要 taskkill**） |
| alist | `0.0.0.0:5244` | `D:\alist\start.bat` | 重启该脚本 |

> ⚠️ 局域网服务对外地址是 **`192.168.0.8`**（WLAN 网卡）。
> 本机双网卡（WLAN `.0.8` / 有线 `.0.9`）出口会漂移，排查连通性先确认出口网卡。

---

## 5. 与自动化的同步约定

**改了任一脚本的调用方式/参数，必须同步修改对应的 automation prompt。**

原因：automation 里存的是一条完整的命令序列，脚本参数变了而 prompt 没变，
会出现「跑了一半、参数还是旧的」这类静默错误。
